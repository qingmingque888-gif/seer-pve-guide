# 04 · 数据规范（data.json 字段说明）

`data.json` 是唯一数据事实源，HTML 内嵌兜底数据必须与它一致。

## 顶层结构
- `version`：数据版本号，建议用日期 `YYYY-MM-DD`
- `updatedAt`：数据最后更新日期
- `days`：时间线数组（第 N 天）
- `levels`：关卡数组
- `pets`：宠物数组

## days 字段
- `day`：第几天（整数）
- `title`：显示标题，如「第 1 天」
- `todo`：当日必做清单（字符串数组）
- `unlockLevels`：该天解锁的关卡 id 数组（对应 `levels[].id`）

## levels 字段
- `id`：唯一英文 id（kebab-case），如 `level-puni-seal`
- `name`：关卡名
- `category`：分类（用于分组），如「谱尼」「怒雷神裁·雷伊」
- `day`：建议挑战的登录天数（整数，供时间线关联）
- `difficulty`：难度 1~5（整数）
- `recommendedPets`：推荐宠物数组，每项 `{ petId, role, note }`
- `requiredPets`：通关所需宠物 id 数组
- `steps`：分步攻略（字符串数组）
- `tips`：注意事项（可选）

## pets 字段
- `id`：唯一英文 id（kebab-case），如 `starlight-lux`
- `name`：宠物名
- `type`：属性（如「水系」）
- `role`：定位（如「全能强攻 / 坦克」）
- `obtain`：获取方式
- `moveset`：配招（字符串数组）
- `build`：养成对象，键为「学习力 / 性格 / 天赋 / 特性 / 刻印 / 抗性」等，值为字符串
- `note`：机制说明（可选）
- `tips`：打法提示（可选）

## 约定
1. id 全站唯一；关卡用 `level-` 前缀，宠物用有意义的英文名。
2. 所有 `petId` / `unlockLevels` / `requiredPets` 的引用必须能对上对应的 id，否则渲染会断链。
3. 不确定的数值在文案里标注「待核对」，禁止编造。
4. 新增内容先改 data.json，再同步到 HTML 内嵌 `EMBEDDED_DATA`。
